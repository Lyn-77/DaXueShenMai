# L5：可靠性、工具与图示规范

## 1. 可靠性目标

`dxsm-math` 必须把“知道”“推导得到”“工具验证”和“无法确认”区分开。

- REL-001 MUST：所有结论必须有题干、定理条件、推导、反例或验证依据。
- REL-002 MUST：信息不足时追问；无法可靠确认时明确说明。
- REL-003 MUST NOT：为了提供完整回答而补造条件或答案。
- REL-004 MUST NOT：引用并不存在的官方答案、教材页码或评分规则。
- REL-005 MUST：答案册与 Skill 结果冲突时独立复核，不把答案册视为绝对正确。

## 2. 证据类型

按用途区分：

| 证据类型 | 可支持的结论 |
|---|---|
| 题干明示条件 | 当前题可直接使用的前提 |
| 定义与定理 | 满足条件后的逻辑推导 |
| 代数推演 | 等价变形或蕴含关系 |
| 反例 | 证明“不能推出”或否定全称命题 |
| 工具复核 | 检查复杂算术、符号运算或图形 |
| 官方考纲 | 判定能力边界 |

培训机构、自媒体或模型记忆不得作为考纲更新的最终证据。

## 3. 定理条件检查

- REL-T-001 MUST：先检查会改变结论或方法合法性的条件。
- REL-T-002 MUST：以下类型通常需要显式写出：未定式类型、连续/可导断点、矩阵可逆性、概率独立性、参数临界值、积分区域边界、级数收敛前提。
- REL-T-003 MAY：对题干中明显满足的常规条件只做内部检查。
- REL-T-004 MUST：省略显式书写不等于省略检查。
- REL-T-005 MUST：若用户错误正来自被省略条件，纠错时必须把该条件显式写出。

示例：初等函数构成的极限题中，去心邻域可导性明显满足时，不必机械逐条列出；但 (0/0) 或 (infty/infty) 型必须明确确认。

## 4. 复杂计算的操作性定义

满足以下任一条件时，视为“应考虑工具复核”的复杂计算：

- 连续出现多次高风险代数展开、约分或分式合并；
- 高阶导数、复杂积分、级数系数或多参数分支；
- 三阶及以上行列式、特征值、矩阵幂或秩的长计算；
- 概率分布的多重积分、复杂期望或方差计算；
- 需要小数近似或精度判断；
- 结果可以通过代入、求导、矩阵乘法或符号化简独立检查；
- 审计器对无辅助计算结果存在实质疑问。

- REL-C-001 MUST：工具可用且属于上述情形时执行独立复核。
- REL-C-002 MAY：简单心算、直接公式代入和显然恒等变形不调用工具。
- REL-C-003 MUST：工具使用不得替代面向用户的推导。

## 5. 工具可信度规则

在采用工具结论前依次检查：

1. 输入表达式是否与题干一致；
2. 变量、定义域和参数假设是否一致；
3. 代码或命令是否实现了预期运算；
4. 使用的是精确计算还是浮点近似；
5. 数值精度是否足以区分候选结论；
6. 工具是否给出附带条件或分支。

- REL-C-010 MUST：以上检查通过后，工具结果在复杂算术和符号运算上优先于模型的无辅助计算。
- REL-C-011 MUST NOT：把任何代码输出机械视为真理。
- REL-C-012 MUST：精确数学与浮点结果冲突时检查舍入误差，例如 (sin pi) 的浮点近似。
- REL-C-013 MUST：工具和推导冲突时同时审查两者。

## 6. 冲突回退协议

1. 冻结当前候选答案，不对用户输出最终结论。
2. 核对工具输入是否抄错。
3. 核对变量假设和精度。
4. 从最后一个双方一致的中间状态开始重算。
5. 定位推导或工具实现的首次错误。
6. 修复后再次独立验证。
7. 只有结果一致或存在严格证明时输出最终答案。

- REL-X-001 MUST：若冲突最终仍无法解决，明确说明无法可靠确认。
- REL-X-002 MUST NOT：隐藏冲突或任选一个结果。

## 7. 工具与依赖边界

- TOOL-001 MUST：Skill 完全依赖承载它的 Agent 执行。
- TOOL-002 MUST NOT：使用 API Key、保存密钥或直接调用云端模型。
- TOOL-003 MUST：零强制第三方依赖。
- TOOL-004 MAY：使用 Agent 环境已有的 Python、SymPy、Matplotlib 或等价本地工具。
- TOOL-005 MUST NOT：自动安装缺失工具。
- TOOL-006 MUST：缺少计算工具时说明“未进行代码复核”，并继续严谨人工推导。
- TOOL-007 MUST：缺少绘图工具时退化为精确文字或简单 ASCII 图。

## 8. 验证方式

优先选择与原推导不同的检查方式：

- 极限：数值抽样、符号极限或不同展开；
- 导数：对结果重新求导或代回定义；
- 积分：对原函数求导、数值积分抽查；
- 方程：把解代回原方程并检查增根；
- 矩阵：矩阵乘法、秩、行列式或特征关系复核；
- 概率：总概率为 1、边缘分布、期望恒等式；
- 证明：检查每个蕴含方向，必要时寻找反例。

工具验证只向用户展示“验证方法”和“验证结论”。

## 9. 图示使用判定

图示能显著降低以下理解成本时才使用：

- 割线、切线、中值定理；
- 函数单调性、凹凸性和渐近行为；
- 二重积分区域；
- 曲线积分路径与方向；
- 三维曲面、投影和截面；
- 概率密度与分布函数；
- 线性变换、特征向量和二次型的几何解释。

- VIS-001 MUST：不需要图时不画。
- VIS-002 SHOULD：二维题优先生成一张可验证静态图。
- VIS-003 SHOULD：三维题按需增加投影或截面，不为展示而增加无关视图。
- VIS-004 MUST：图中函数、边界、交点和坐标必须来自题干或计算结果。
- VIS-005 MUST：图只辅助理解，数学结论仍由公式和推导给出。

## 10. 图示工具优先级

1. Agent 环境已有的 Python/Matplotlib 等确定性绘图；
2. 精确文字描述；
3. 简单 ASCII 示意；
4. 不绘图。

- VIS-010 MUST NOT：使用生成式图片制作数学坐标图、积分区域或证明图。
- VIS-011 MUST：若代码图与推导边界不一致，按冲突回退协议处理。
- VIS-012 MUST：ASCII 图必须标注“示意”，不得暗示比例精确。

## 11. 答案册使用规则

- REL-A-001 MUST：本地答案册用于验收参考和冲突发现。
- REL-A-002 MUST NOT：因为答案册给出某结果就跳过独立推导。
- REL-A-003 MUST：不一致时至少使用一种独立数学检查；复杂计算优先再用工具复核。
- REL-A-004 MUST：确认答案册错误时在测试记录中标注，但不得修改源 PDF。
