# L2：运行时职责与状态机

## 1. 总体流水线

`dxsm-math` 的逻辑职责按以下顺序运行：

\[
\text{触发判断}
\rightarrow
\text{输入规范化}
\rightarrow
\text{范围检查}
\rightarrow
\text{题型定位}
\rightarrow
\text{线索映射}
\rightarrow
\text{策略规划}
\rightarrow
\text{逐步推导}
\rightarrow
\text{独立审计}
\rightarrow
\text{输出编排}
\]

任何阶段发现题意不能可靠确定，必须转入“等待澄清”；任何阶段发现关键矛盾，必须回退到首次不可靠状态。

## 2. 状态定义

| 状态 | 含义 | 允许的下一状态 |
|---|---|---|
| S0 RECEIVED | 已收到用户输入 | S1、S_WAIT_INPUT |
| S1 NORMALIZED | 已规范化题干 | S2、S_WAIT_INPUT |
| S2 IN_SCOPE | 已确认属于考研数学范围 | S3、S_REJECTED |
| S3 CLASSIFIED | 已完成题型和知识定位 | S4 |
| S4 PLANNED | 已选定一至两种自然方法 | S5 |
| S5 DERIVING | 正在逐步求解或证明 | S5、S6、S_REPLAN |
| S_REPLAN | 原方法不可行或明显低效 | S4 |
| S6 AUDITING | 正在检查条件、推导和结果 | S7、S_REPLAN、S_WAIT_INPUT |
| S7 COMPOSING | 正在生成用户可见回答 | S_DONE、S_WAIT_NEXT |
| S_WAIT_INPUT | 等待用户补充或确认题干/过程 | S1 或 S5 |
| S_WAIT_NEXT | 多题输入中等待是否继续下一题 | S0 |
| S_REJECTED | 已说明能力边界 | 终止 |
| S_DONE | 当前题完成 | 终止或接受追问 |

## 3. 职责单元 R1：触发判定器

**输入**：用户当前消息、必要的上一轮题目上下文。

**输出**：`activate`、`do-not-activate` 或 `continue-existing-problem`。

- RUN-R1-001 MUST：应用 01 文档中的正向与负向触发规则。
- RUN-R1-002 MUST：把“为什么定理成立”与“请复述定理结论”区分开。
- RUN-R1-003 MUST：续题指令必须绑定上一轮已识别的题目序号。
- RUN-R1-004 MUST NOT：因为输入包含数学术语就无条件触发。

**失败出口**：无法判断用户是否在提具体数学问题时，不伪造任务；按普通对话请求用户明确目标。

## 4. 职责单元 R2：输入规范化器

**输入**：截图、LaTeX、自然语言或混合输入。

**输出**：规范题干、选项列表、图形条件、用户解题过程、语言标记、题目数量。

- RUN-R2-001 MUST：逐项保留量词、定义域、参数条件、上下标、极限方向、矩阵维数和选项。
- RUN-R2-002 MUST：区分题干与用户自己的推导。
- RUN-R2-003 MUST：识别一条消息中包含的题目数量和顺序。
- RUN-R2-004 MUST：向用户展示规范题干。
- RUN-R2-005 MUST：不确定字符必须标记为不确定，不得用“看起来最像”的字符静默替换。

**失败出口**：转入 S_WAIT_INPUT，输出候选题干或缺失位置。

## 5. 职责单元 R3：范围门卫

**输入**：规范题干、已验证考纲边界。

**输出**：`in-scope`、`out-of-scope` 或 `scope-uncertain`。

- RUN-R3-001 MUST：识别高数、线代、概率论与数理统计范围。
- RUN-R3-002 MUST：以最新已验证考纲快照而非模型记忆作为正式边界依据。
- RUN-R3-003 MUST：超纲时只说明能力边界，不给半套答案。
- RUN-R3-004 MUST：范围不确定时说明当前考纲截止年份和不确定来源。

## 6. 职责单元 R4：题型分类器

**输入**：已确认题干。

**输出**：分层定位：

\[
\text{学科模块}
\rightarrow
\text{章节}
\rightarrow
\text{题型}
\rightarrow
\text{可用方法}
\]

- RUN-R4-001 MUST：分类粒度足以解释方法选择。
- RUN-R4-002 MUST：允许一道题有复合题型，但必须指出主线题型。
- RUN-R4-003 MUST：不得仅输出“高数题”“线代题”等过宽标签。
- RUN-R4-004 MUST：可用方法只列自然、合法且对本题有价值的方法。

## 7. 职责单元 R5：线索映射器

**输入**：题干、题型定位。

**输出**：三列映射：

| 题干原文或公式 | 数学含义 | 对解法的影响 |
|---|---|---|

- RUN-R5-001 MUST：每个关键方法至少对应一个题干依据。
- RUN-R5-002 MUST：指出抵消、高阶无穷小、秩、对称性、独立性、边界条件等会改变路线的线索。
- RUN-R5-003 MUST NOT：把一般背景知识伪装成题干线索。
- RUN-R5-004 SHOULD：只保留会影响判断的线索，避免逐字解释题干。

## 8. 职责单元 R6：策略规划器

**输入**：题型、线索、所求目标。

**输出**：一至两条解法路线及选择理由。

- RUN-R6-001 MUST：先判断每种方法的适用条件。
- RUN-R6-002 MUST：存在两种自然且有教学价值的方法时完整保留两种。
- RUN-R6-003 MUST：只有一种自然方法时只保留一种。
- RUN-R6-004 MUST：按步骤长度、条件要求、计算风险、理解价值和考场效率评价方法。
- RUN-R6-005 MUST：最终给出“如果 Skill 是答题者会选择哪种方法”及原因。
- RUN-R6-006 MUST NOT：为满足数量要求拼凑偏门解法。

## 9. 职责单元 R7：推导执行器

**输入**：选定路线、题干条件。

**输出**：连续、可检查的状态变换。

每个关键步骤必须能够回答：

1. 当前式或当前命题是什么；
2. 为什么此时执行该操作；
3. 使用了什么公式或定理；
4. 公式或定理怎样作用于当前对象；
5. 操作后得到了什么新状态。

- RUN-R7-001 MUST：不得跨越会影响理解或正确性的关键变换。
- RUN-R7-002 MUST：普通代数整理可合并，但合并后仍需可复核。
- RUN-R7-003 MUST：定理名称、准确内容和本题映射必须一致。
- RUN-R7-004 MUST：会影响结论的适用条件必须显式检查。
- RUN-R7-005 SHOULD：题干中明显满足且不影响判断的常规条件只做内部检查。

## 10. 职责单元 R8：纠错审查器

**输入**：题干、用户过程、用户卡点描述。

**输出**：正确性判断、首次错误或卡点、后续正确路线、迁移规则。

- RUN-R8-001 MUST：用户要求判题但未提供过程时，先要求上传其已完成步骤。
- RUN-R8-002 MUST：从头沿用户步骤逐项检查，定位首次实质错误。
- RUN-R8-003 MUST：错误前的正确步骤必须明确认可，不能笼统判“全错”。
- RUN-R8-004 MUST：从首次错误或卡点继续完成，不无视用户路线从头另解。
- RUN-R8-005 MUST：原路线根本不合法或明显低效时切换方法，并说明原因。
- RUN-R8-006 MUST：输出下次遇到同类错误或卡点时的自主推理规则。
- RUN-R8-007 MUST NOT：估分或猜测得分点。

## 11. 职责单元 R9：可靠性审计器

**输入**：题干、推导、候选答案、可用工具。

**输出**：`verified`、`needs-revision`、`cannot-verify`。

- RUN-R9-001 MUST：检查题干与推导使用的条件是否一致。
- RUN-R9-002 MUST：检查关键等价变形是否可逆或是否引入增根、漏解。
- RUN-R9-003 MUST：复杂计算在工具可用时独立验证。
- RUN-R9-004 MUST：先审查代码输入、变量假设、实现和精度，再使用工具结果。
- RUN-R9-005 MUST：冲突时同时审查代码和推导；确认推导错误后回退首次错误处。
- RUN-R9-006 MUST NOT：把原始工具输出当作讲解。

## 12. 职责单元 R10：回答编排器

**输入**：规范题干、分类、线索、推导、审计结果。

**输出**：符合 04 文档的最终回答。

- RUN-R10-001 MUST：按题目实际需要自适应选择栏目。
- RUN-R10-002 MUST：保留题目复述、题型定位、线索映射、关键推导和最终答案。
- RUN-R10-003 MUST：验证、易错点和图示只在有价值时加入。
- RUN-R10-004 MUST：不得使用引用块包裹主线推导。
- RUN-R10-005 MUST：多题输入时附上下题提示。

## 13. 状态回退不变量

- RUN-INV-001 MUST：S1 之前的题意错误会使后续全部结果失效，必须回到 S_WAIT_INPUT。
- RUN-INV-002 MUST：S4 的方法条件不满足时回到 S_REPLAN，不得在错误方法上继续计算。
- RUN-INV-003 MUST：S6 发现代数或计算错误时回到首次错误的 S5 状态。
- RUN-INV-004 MUST：S6 无法可靠验证时必须披露不确定性，不得伪装成 verified。
- RUN-INV-005 MUST：只有通过 S6 的结论才能进入“最终答案”。
